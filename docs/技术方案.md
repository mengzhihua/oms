# OMS 技术方案

OMS 是订单中枢，不是控制塔。它自己完成接单、审核、分仓、预占、推仓和售后。IR 只拉快照、下协同指令。

## 1. 运行位置

| 场景 | 后端 | 说明 |
| --- | --- | --- |
| 单机 | `8080` | `application.yml` |
| 与控制塔同机 | `8081` | IR `ct_system` 种子 |

默认演示账号 `admin / admin123`。开放接口鉴权是请求头 `X-Api-Key`，种子键 `oms-open-key`。`/api/open/**` 不走登录令牌。

## 2. 主链路

```text
渠道/手工下单 → CREATED → AUDITED → 分仓预占 ALLOCATED
    → 推出库 PUSHED → WMS 发货 SHIPPED → TMS 签收 COMPLETED
已经完成的订单再次收到签收，保持完成，不再追加签收日志。
挂起只允许 CREATED / AUDITED；解除挂起回到挂起前的状态。
待审核或已审核、同一客户同一地址的订单可以合单。时间窗优先用请求里的分钟，否则用店铺上的合单窗口，都没填则 30 分钟。来源单变为已合单，明细并入目标单，同一 SKU 数量相加。已分仓及之后的订单不合。
```

取消允许 `CREATED / AUDITED / HOLD / ALLOCATED / PUSHED`。已分仓或已推仓取消时释放预占，已推仓还要通知 WMS。

`oms.integration.mock=false` 时，推出库打到 WMS `POST /api/open/outbound`，发货后打到 TMS `POST /api/open/transport-order`，并带上 `X-Api-Key`。地址为空会记失败，不再返回模拟单号。默认地址是 WMS `8083`、TMS `8082`。同一开关下，发货还会把交货过账到 SAP `POST /api/open/events/delivery`（默认 `8085`）。模拟模式只在订单上记下 `DN-` 加订单号，不额外写集成日志。

## 3. 控制塔读

`GET /api/open/ir/snapshots` 返回三块，避免控制塔再去拼登录分页和报表：

| 块 | 内容 |
| --- | --- |
| `orders` | 销售订单，含首行 SKU 和数量 |
| `inventory` | 渠道可售库存 |
| `sales` | 按日、SKU、仓、渠道的销量 |

## 4. 控制塔写

统一口 `POST /api/open/ir/actions`。旧版本没有统一口时，控制塔回退专用口。请求体带 `type`、`targetKey`（订单号）、`params`、`idempotencyKey`。

| 指令 | 专用口 | 作用 |
| --- | --- | --- |
| `OMS_HOLD` | `POST /api/open/ir/hold` | 挂起。只接受 `CREATED` / `AUDITED` |
| `OMS_UNHOLD` | `/unhold` | 解除挂起，回到挂起前的 `CREATED` 或 `AUDITED` |
| `OMS_REROUTE_WAREHOUSE` | `/reroute` | 按 `params.warehouseCode` 改仓 |
| `OMS_AUTO_PROCESS` | `/auto` | 一键处理 |
| `OMS_CANCEL` | `/cancel` | 取消 |
| `OMS_PRIORITIZE` | `/prioritize` | 改备注并提高优先级，默认 10 |

没有 API Key 时，控制塔登录后改打业务口：`/hold`、`/unhold`、`/reroute`、`/auto`、`/cancel` 对应 `POST /api/order/{orderNo}/…`；加急对应 `POST /api/order/{orderNo}/remark`。

非空幂等键按 `type|订单号|key` 缓存。空键每次执行。

## 5. 边界

OMS 不保存控制塔的决策。挂起只接受已创建、已审核。解除挂起回到挂起前的状态。已支付未发货的加急仍走 `OMS_PRIORITIZE`，不把挂起放宽到已支付之后。
