## 1. 项目概述

### 1.1 背景与定位

OTWB（OMS / TMS / WMS / BMS）是供应链一体化系统群，其中 **OMS（Order Management System，订单管理系统）是整个链路的"大脑"**：

- **对上**：统一承接来自各销售渠道（电商平台、线下门店、经销商 DMS 等）的订单；
- **对内**：完成订单审核、拆单、分仓路由、库存预占 / 扣减、售后处理；
- **对下**：把履约指令下发 WMS（仓库作业）和 TMS（运输配送），并接收发货 / 签收回传，驱动订单状态闭环。

## 2. 技术架构

### 2.1 技术选型

与已建成的 WMS / TMS 系统保持同一技术栈，降低团队学习和运维成本。

| 层次 | 技术 |
|---|---|
| 后端 | Java 17、Spring Boot 2.7、MyBatis-Plus 3.5 |
| 前端 | Vue 3、Vite 5、Element Plus、Vue Router、Axios |
| 数据库 | MySQL 8（生产）/ H2（本地与测试，零依赖启动） |
| 鉴权 | 自研 Token（HMAC 签名，TTL 可配）+ 角色访问策略 |
| 集成 | REST + JSON，Bearer Token（内部）/ `X-Api-Key`（开放接口） |
| 构建 | Maven、npm |

## 3. 核心业务流程

### 3.1 销售订单状态机

```mermaid
stateDiagram-v2
    [*] --> CREATED: 渠道下单 / 手工 / 导入
    CREATED --> AUDITED: 审核（店铺自动审核且已付款可自动）
    CREATED --> HOLD: 挂起
    HOLD --> CREATED: 解挂
    AUDITED --> ALLOCATED: 分仓路由 + 库存预占（缺货自动拆单）
    ALLOCATED --> PUSHED: 推送 WMS 出库单
    PUSHED --> SHIPPED: WMS 发货回传（扣减库存、生成 TMS 运单）
    SHIPPED --> COMPLETED: TMS 签收回传 / 人工确认完成
    CREATED --> CANCELLED: 取消
    AUDITED --> CANCELLED: 取消
    ALLOCATED --> CANCELLED: 取消（释放预占）
    PUSHED --> CANCELLED: 取消（通知 WMS 撤单，释放预占）
    COMPLETED --> [*]
    CANCELLED --> [*]
```

**关键规则**

- **分仓路由**：按 `店铺 → 省份/城市 → 优先级` 匹配 `oms_routing_rule`，选择有货的最优仓；无规则时回退店铺默认仓。
- **自动拆单**：单仓无法满足全部明细时，按可用库存拆成多张子单分别分仓。
- **组合商品**：下单时按 BOM 自动拆解为子 SKU 明细，库存以子 SKU 计算。
- **一键处理**：`审核 → 分仓 → 推 WMS` 一步完成，支持列表批量操作。

### 3.2 端到端履约时序

```mermaid
sequenceDiagram
    participant CH as 渠道 / DMS
    participant OMS
    participant WMS
    participant TMS
    CH->>OMS: POST /api/open/channel/orders（X-Api-Key）
    OMS-->>OMS: 创建订单 → 自动审核 → 分仓 → 预占库存
    OMS->>WMS: 出库单（WmsAdapter）
    WMS-->>OMS: POST /api/open/wms/shipped 发货回传
    OMS-->>OMS: 扣减库存、状态 SHIPPED
    OMS->>TMS: 创建运单（TmsAdapter）
    OMS-->>CH: 发货状态回推（DMS 渠道）
    TMS-->>OMS: POST /api/open/tms/track 在途轨迹
    TMS-->>OMS: POST /api/open/tms/signed 签收
    OMS-->>OMS: 状态 COMPLETED
    OMS-->>CH: 签收状态回推（DMS 渠道）
```

### 3.3 库存模型

```mermaid
flowchart LR
    A[在库 qtyOnHand] -->|分仓| B[预占 qtyReserved]
    B -->|发货回传| C[扣减 在库-预占同减]
    B -->|取消订单| A
    D[退货入库回传] -->|回增| A
    E[WMS 库存同步 /open/wms/inventory] -->|覆盖| A
    A --> F[可用 = 在库 - 预占]
    F -->|渠道库存策略<br/>比例 / 固定 / 安全库存| G[渠道可售库存]
```

所有库存变动均写入 `oms_inventory_txn` 流水，可按 SKU / 仓库 / 类型追溯。

### 3.4 售后流程

```mermaid
stateDiagram-v2
    [*] --> CREATED: 基于已发货/已完成订单创建
    CREATED --> AUDITED: 审核
    CREATED --> REJECTED: 驳回
    AUDITED --> RECEIVED: WMS 退货入库回传（库存回增）
    AUDITED --> REFUNDED: 仅退款(REFUND_ONLY) 直接退款
    RECEIVED --> REFUNDED: 退款（生成退款记录）
    RECEIVED --> COMPLETED: 换货(EXCHANGE) 自动生成 0 元换货订单
    REFUNDED --> COMPLETED
    COMPLETED --> [*]
    REJECTED --> [*]
```

| 类型 | 说明 |
|---|---|
| RETURN 退货退款 | 审核后推 WMS 退货入库单；收货回增库存后退款完成 |
| REFUND_ONLY 仅退款 | 审核后直接退款完成，不涉及库存 |
| EXCHANGE 换货 | 收货后自动创建 0 元换货销售订单并走正常履约 |

## 5. 开放接口（Open API）

所有开放接口位于 `/api/open/**`，通过请求头 `X-Api-Key` 鉴权，供渠道 / WMS / TMS 调用。

| 方向 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 渠道→OMS | POST | `/api/open/channel/orders` | 渠道下单（按店铺+渠道单号幂等） |
| 渠道→OMS | GET | `/api/open/channel/orders/{shopCode}/{channelOrderNo}` | 查询订单状态 |
| 渠道→OMS | POST | `/api/open/channel/orders/cancel` | 渠道取消 |
| 渠道→OMS | GET | `/api/open/channel/inventory?shopCode=&skus=` | 查询渠道可售库存 |
| WMS→OMS | POST | `/api/open/wms/inventory` | 库存同步 |
| WMS→OMS | POST | `/api/open/wms/shipped` | 发货回传 |
| WMS→OMS | POST | `/api/open/wms/return-received` | 退货入库回传 |
| TMS→OMS | POST | `/api/open/tms/track` | 在途轨迹 |
| TMS→OMS | POST | `/api/open/tms/signed` | 签收回传 |
| OMS→WMS/TMS | — | `WmsAdapter` / `TmsAdapter` | 出库单、撤单、退货入库单、运单创建 |
| OMS→DMS | — | `IntegrationService` | DMS 渠道订单发货 / 签收 / 取消状态回推（尽力而为，失败仅记日志） |

## 7. 部署与运行

```bash
# 后端（默认 H2 内存库，零依赖）
cd backend && OMS_OPEN_API_KEY=dev-key mvn spring-boot:run     # http://localhost:8080

cd frontend && npm install && npm run dev                      # http://localhost:5173
```

## 9. 后续规划与建议

1. **生产联调**：切换 MySQL，配置真实 WMS / TMS 地址关闭 mock，联调出库单 / 运单 / 回传全链路。
2. **渠道扩展**：在 Open API 基础上增加天猫 / 抖音 / 拼多多等平台适配器与订单自动拉取任务。
3. **可靠性增强**：对下游调用引入重试队列与失败告警（当前接口日志已具备失败统计）。
4. **性能与运维**：接入 CI（构建 + 测试 + smoke）、容器化部署、监控与日志采集。
5. **业务深化**：促销 / 优惠拆分、预售与缺货预警、多币种、物流费用对账（对接 BMS）。
